## 1. 五分钟上手

需要 Python 3.11+ 与 Node 20.19+（或 22+）。

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e ".[dev]"
cd web; npm ci; cd ..
```

```bash
python3 -m venv .venv && ./.venv/bin/python -m pip install -e ".[dev]" && (cd web && npm ci)
```

日常开发用**两个进程**（前端有 HMR），验证交付形态用**一个进程**：

| 模式 | 启动 | 什么时候用 |
| --- | --- | --- |
| 双进程 | 后端 `uvicorn --reload`（:8000）+ 前端 `npm run dev`（:5173） | 改前端，改后端热重载 |
| 单进程 | `cd web && npm run build` 后 `python -m app.main`（:8000 同时给页面与接口） | 验证交付形态、跑浏览器端到端 |

```powershell
# 后端（双进程模式）
.\.venv\Scripts\python.exe -m uvicorn app.main:create_app --factory --reload

# 前端
cd web; npm run dev            # http://localhost:5173，/api 代理到 127.0.0.1:8000

# 单进程
cd web; npm run build; cd ..
.\.venv\Scripts\python.exe -m app.main
```

前端代理目标可以用 `WELEARN_BACKEND` 改（`web/vite.config.ts` 读取），所以能让 5173 指向
别的后端（比如下面要说的桩服务）。

### 常用命令

| 目的 | 命令 |
| --- | --- |
| 全量测试 | `.\.venv\Scripts\python.exe -m pytest tests` |
| 单个文件 / 单个用例 | `... -m pytest tests/test_teaching_service.py`、`... -m pytest "tests/test_api_closed_loop.py::test_teach_skip_node"` |

## 2. 零成本联调：假 LLM 桩

`scripts/dev_stub_server.py` 起的是一个**真实服务端**，只把 LLM 客户端替换成桩。
SSE 分帧、事件处理、状态机、三选一、刷新恢复全都走真实代码，可以无限次重跑而不花一分钱。

```powershell
# 建议用非默认端口 + 临时数据目录，避免碰自己的真实数据
$env:WELEARN_STUB_PORT='8100'
$env:WELEARN_STUB_DATA_DIR="$env:TEMP\welearn-dev"
.\.venv\Scripts\python.exe scripts\dev_stub_server.py
```

```powershell
# 另开一个终端：前端指向桩后端
$env:WELEARN_BACKEND='http://127.0.0.1:8100'
cd web; npm run dev -- --port 5300
```

| 环境变量 | 作用 |
| --- | --- |
| `WELEARN_STUB_PORT` | 监听端口，默认 8000（会与真实后端冲突，建议改） |
| `WELEARN_STUB_DATA_DIR` | 数据目录，未设置则用临时目录（每次启动都是干净的） |
| `WELEARN_HOST` | 监听地址，默认 127.0.0.1 |

桩的判定规则是"回答 **≥40 字**算通过"，只区分 pass / fail（没有 partial）。
因此可以手工制造出完整失败路径：短答 → 未通过 → 换角度重讲 → 连续失败 → 三选一。
要验证"部分通过"的分支，用 `tests/stubs.py` 的 `json_response()` 在单测里给判定脚本，
或改桩的 `_verdict()` 自己造。

桩还会返回固定余额（`CNY 88.80`）与模型列表，方便验证成本、余额与设置页。

> **不要**把桩指向真实数据目录：它会在库里创建测试主题，混进你的学习记录。

```text
                        # / Review / Archive / Search / Settings / NotFound / StageRedirect
  utils/download.ts     # Blob 下载

```

**分层约束**（违反它代码会很快变成一团）：

| 层 | 可以调用 | 不可以 |
| --- | --- | --- |
| `api/` | `services/`、`contracts/`、`infra/` 的纯函数；`ctx.llm` 的纯透传方法（余额、测试连接、模型列表） | 直接写 SQL、拼业务提示词或调 agent、自己判断状态机 |
| `services/learning/` | `services/llm/`、`infra/`、`LearningStack` | 触碰 FastAPI 的 `Request`/`HTTPException` |
| `services/llm/` | `infra/deepseek/`、`contracts/` | 反向依赖 `services/learning/` |
| `infra/` | 标准库与第三方库 | 依赖上面三层 |

跨层一律经 `LearningStack`（`app/services/learning/stack.py`）：它是"装配好的领域服务集合"，
测试与应用启动都从这里取服务。新增服务时**同时**加到 stack，否则测试里装配不出来。

## 4. 改代码前必须知道的不变量

这些是项目里"看起来可以简化、实际一改就坏事"的地方。

### 4.1 状态机与待答问题

- 主题状态（`draft → assessing → path_review → teaching → completed`，另有 `paused`）只能经
  `services/learning/state.py` 迁移；接口层不做状态判断，只把 service 抛的域错误映射成 409。
- `pending_question` 由"最后一条 assistant 消息"推出。因此**失败的一轮绝不能把用户输入写进记忆**，
  否则最后一条变成用户消息，`pending_question` 变 `null`，界面既看不到问题也重试不了。
- 测评的 `transcript` 任何状态都返回（支持回放），但 `pending_question` **只在测评进行中**非空——
  否则结束后最后一条画像结论会被当成待答问题。

### 4.2 记忆三层与压缩

- 三类记忆互相隔离：测评 / 教学 / 复习各一个容器，复习不碰 `current_node_id`。
- 一轮失败（超时、空内容、网络中断）不得写入记忆；只有产出正文才算成功，停止生成则保留部分内容并提交。
- 压缩前记录内容指纹，应用时校验；压缩期间新增的轮次不能丢（有专门测试锁住）。

### 4.3 契约是冻结的

`app/contracts/` 里的事件与结构化输出 schema 一旦改动，必须**同时**做三件事：
改代码、更新 [接口契约](接口契约.md)、在 [接口契约变更记录](接口契约变更记录.md) 追加一节。
前端只按事件名消费，不解析文本；新增事件必须给前端一个默认忽略的分支。

### 4.4 SSE 约定

- 流式端点**一律返回 200**，业务错误作为 `error` 事件下发（带 `category`）；只有"主题不存在"
  这类请求级错误才在建立流之前抛 404。
- 前端不解析原始 SSE 文本，交给 `api/sse.ts`；代理层必须禁缓冲（vite 已设 `no-transform`）。
- `error` 事件的文案是给用户看的，必须"发生了什么 + 可以做什么"，不能带堆栈与绝对路径。

### 4.5 Key 与脱敏

- 明文只允许出现在两个瞬间：写入加密存储、以及实际请求的请求头。
- 所有出口（设置、健康、用量、模型列表、余额、测试连接、导出、日志）只允许掩码。
- 上游返回的错误体可能回显 Key，因此错误详情在进入日志与响应前都要过 `infra/redaction.py`。

### 4.6 用量与成本

- 每条用量记录带发生时刻，成本按那一刻的单价逐条计算（高峰：工作日 9–12、14–18，其余半价）。
- 工具轮内多次请求合并成一条用量：token 准确，`calls` 只计轮数（已知取舍，见实施计划遗留清单）。

### 4.7 工具调用

- **永不下发 `tool_choice`**：思考模式指定工具会直接 400。
- **仅 DeepSeek**：携带 `tools` 时历史 `reasoning_content` 必须原样回传，否则上游报错；
  通用 OpenAI 兼容接口不要求，且可能拒收，因此那里一律剔除（见 §4.9）。
- 工具执行失败不抛给用户，作为结果文本回给模型，让模型自己改口。

### 4.9 供应商能力档案（P6）

`app/infra/llm/providers.py` 是"发什么、怎么读"的唯一事实来源。**不要**在客户端或协议层
写 `if provider == ...`——加一家新服务应当是加一份档案数据，而不是加分支。

| 能力位 | DeepSeek | OpenAI 兼容 | 写错的后果 |
| --- | --- | --- | --- |
| `send_thinking` | ✅ 下发 `thinking` | ❌ 不下发 | 发给不认它的网关 → 400 |
| `send_reasoning_effort` | ✅ low/high/max | ✅ low/high（`max`→`high`） | 越界取值 → 400 |
| `reasoning_fields` | `reasoning_content` | `reasoning_content` / `reasoning` | 思维链丢失（不报错，只是看不见） |
| `cache_hit_fields` / `cache_details_field` | `prompt_cache_*` | `prompt_tokens_details.cached_tokens` | **命中与未命中双双为 0，成本少算一半** |
| `echo_reasoning_with_tools` | ✅ 必须回传 | ❌ 剔除 | 回传给严格网关 → 400；不回传给 DeepSeek → 400 |
| `balance_path` | `/user/balance` | `None` | 请求必然 404 的路径，再把 404 翻译成莫名的错误 |
| `off_peak_multiplier` | 0.5 | 1.0 | 给固定价接口算半价，金额少一半 |

**不变量：命中 + 未命中 == 输入总数。** 两家都会优先识别对方形状的缓存字段
（网关可能把 DeepSeek 的字段改写成 OpenAI 写法）；一旦两个桶都读不到，输入 token 会凭空消失。
`tests/test_providers.py::test_usage_never_loses_prompt_tokens_between_the_two_buckets` 锁住这条。

**参数降级**：客户端遇到 `400/422` 且错误正文点名 `reasoning_effort` / `response_format` /
`thinking` / `max_completion_tokens` 时，去掉（或改名）该参数重发一次并记日志。
只认"点名"的情形——把"模型名写错"也当降级重试，只会让用户多等一轮、看到的还是同一个错。

**新增一家服务**：在 `PROFILES` 里加一份 `ProviderProfile`，`ProviderKind` 加一个取值，
再补一条 `test_*_profile_*` 用例。设置页与健康检查会自动带上它（`provider_options` 由档案生成）。

### 4.8 前端

- 所有请求集中在 `web/src/api/{types,client,sse,endpoints}.ts`，页面里不出现裸 `fetch`。
- 不引入 UI 组件库；样式都在 `web/src/index.css`。
- 不允许 `dangerouslySetInnerHTML`，不允许开 `rehype-raw`（安全测试会失败）。
- 流式渲染经 `useTurnStream`，60ms 合帧；**收尾必须先 flush 再置 `streaming=false`**，否则最后一帧会丢。

## 5. 数据库变更流程

`create_all` 只建缺失的表，**不会修改已存在的表**。因此加列必须走列级升级：

1. `app/infra/storage/models.py` 里加字段；
2. `app/infra/storage/db.py` 的 `_COLUMN_UPGRADES` 里登记（先 `PRAGMA table_info` 再 `ALTER TABLE ADD COLUMN`）；
3. `SCHEMA_VERSION` 加 1；
4. `tests/test_schema_upgrade.py` 补"老库 → 新库"用例（含默认值）；
5. 更新 [接口契约 §5](接口契约.md)，并在 [契约变更记录](接口契约变更记录.md) 记录。

**漏登记 `_COLUMN_UPGRADES` 的后果**：新库没问题，老库在运行期报 `no such column`——
而且是那种"某个页面突然 500"的形态，很难第一时间联想到迁移。

想验证迁移链路，直接跑 `tests/test_backup_recovery.py`：它会把 v6 结构的库升到当前版本并断言数据零丢失。

## 6. 测试

### 6.1 夹具

| 夹具 / 工具 | 位置 | 用途 |
| --- | --- | --- |
| `env` | `tests/conftest.py` | 把 `WELEARN_DATA_DIR` 指到临时目录（绝不污染真实数据） |
| `context` | `tests/conftest.py` | 装配好的 `AppContext`（临时库 + 独立 SQLite） |
| `make_client` | `tests/conftest.py` | 注入 `httpx.MockTransport` 的真实客户端 |
| `FakeLlmClient` | `tests/stubs.py` | 按脚本返回流式/非流式响应，或指定 `LlmError` |
| `text_events` / `json_response` / `error_response` | `tests/stubs.py` | 构造事件序列与响应 |
| `make_harness` | `tests/learning_harness.py` | 一套领域服务 + 桩，适合直接测 service |
| `api` | `tests/test_api_closed_loop.py` | 换成桩 LLM 的完整应用 + `TestClient` |

### 6.2 写测试的约定

- 用例 docstring 里标出对应的 FR/NFR/AC 编号：验收时靠它做追溯（SRS 附录 D 就是这么建的）。
- **先证明机制生效，再断言没出问题**。例如测 Key 脱敏：先断言响应里确实出现了掩码，
  再断言各处没有明文；否则"接口返回空"也能让测试绿。
- 越界类测试先用探针证明恶意输入**真的到达了服务端**，再断言读不到文件，避免请求在中间层就被吃掉。
- 涉及写路径的功能，除了单测，还要在真实浏览器里改一次、读回一次（见 §7）。

### 6.3 录制样本

`tests/fixtures/llm/recorded/` 是真实调用的响应（SSE、非流式、JSON Output、模型列表、余额），
由 `tests/test_recorded_fixtures.py` 回放。它同时是**官方结构变化的哨兵**：DeepSeek 改了响应形状，
这个文件会先失败。用 `scripts/llm_smoke.py --record` 更新，更新后必须确认样本里没有 Key。

### 6.4 前端没有测试框架

视觉与交互靠在真实浏览器上验证。用 Playwright（不要装进仓库，放临时目录或全局）：

- **隔离栈**：桩服务 + vite 另开端口（见 §2），不要用真实后端与真实数据。
- 用 `page.keyboard.type()` 而不是 `locator.press()`：后者动作前会自动滚动，污染滚动测量。
- 断言焦点环要**真的按 Tab**：`element.focus()` 不一定命中 `:focus-visible`（脚本聚焦不继承键盘标记），
  否则会得到假阴性。
- 写入类改动必须"改一次 → 刷新 → 读回"，只看构建通过抓不出"编辑被静默丢弃"这类问题（历史上真发生过）。

## 7. 调试

### 7.1 先看健康检查

```powershell
curl.exe http://127.0.0.1:8000/api/health
```

它一次说清五件事，多数"起不来/存不下/调不通"都能从这里定位：

| 字段 | 读法 |
| --- | --- |
| `storage.writable` / `storage.schema_version` | 数据目录能不能写、迁移到第几版（真写探针，不是看权限位） |
| `logs` | 日志目录、级别、是否可写 |
| `api_key.configured` / `source` | Key 有没有配、来自环境变量还是设置页 |
| `llm.configured` / `audit_enabled` | 客户端是否可用、请求审计是否开启 |
| `usage` / `features` | 累计调用与 token；特性开关快照 |

健康检查**永不依赖外部服务**：模型不可用时它也要能回应，否则"服务起没起来"就无从判断。

### 7.2 日志

- 位置：`<数据目录>/logs/`（`app.log` 与 `llm.log`，按大小轮转、按天数清理，均可在设置页调）。
- 级别：设置页「运行与数据」→ 日志级别；改完立即生效。
- **请求审计**：设置页打开 `audit_enabled` 会记录完整请求/响应；若设置读不出来（现场已经乱了），
  用环境变量 `WELEARN_LOG_LLM_PAYLOAD=true` 强制开启（与设置项**取或**）。审计日志同样脱敏。
- 日志是异步队列写的，测试里判断"某条日志有没有落盘"要先 `flush()` 再断言。

### 7.3 症状 → 排查路径

| 症状 | 先查什么 |
| --- | --- |
| 页面白屏 / `/` 404，但 `/api/health` 正常 | 没有 `web/dist`。`cd web && npm run build`；或设 `WELEARN_WEB_DIST` 指过去 |
| 流式回答"憋一大块"才出现 | 中间有代理在缓冲。vite 已设 `no-transform`；自建反代要关 `proxy_buffering` |
| 改了设置保存后不生效 | `PUT /api/settings` 是**整体替换**语义：只提交想改的字段会把其他字段打回默认。前端 `patch` 必须基于当前快照派生草稿；只读字段（`api_key`、`model_plan`、`read_only_fields`）不要回传 |
| 设置页改了 base_url / 模型却总被改回去 | 环境变量优先（`WELEARN_BASE_URL` 等，`.env` 也算）。`GET /api/settings` 的 `env_overridden` 会列出被覆盖的字段，界面也会提示 |
| 换成 OpenAI 兼容后 400「Unsupported parameter」 | 该网关不认某个参数：客户端会自动降级重发一次并记 `已自动降级并重发`。若仍失败，看日志里第一次 400 的正文点名了哪个参数 |
| 老库运行期报 `no such column` | §5：新列没登记 `_COLUMN_UPGRADES` |
| 突然 401 | 实例设过访问口令。`/api/health` 与 `/api/auth/verify` 豁免，其他都要求 `X-Access-Token` |
| SSE 一直 pending 不结束 | 看 `llm.log`：上游超时或连接被关闭；`error` 事件是否发出 |
| 判定总是"未通过" | 桩模式下看回答长度（≥40 字）；真实模式下打开审计看判定原始 JSON |
| 压缩后再提问像"失忆" | 压缩摘要只保留结论，冷启动是预期代价；看日志里的压缩事件与指纹校验 |
| 前端请求 404 但接口存在 | 检查路径前缀 `/api` 与 `web/src/api/endpoints.ts` 是否一致 |

### 7.4 手工调接口

## 8. 前端开发要点

- **数据获取**：只读用 `useResource`（自带 loading/error/reload），写操作直接调 `endpoints`。
- **外壳不要换骨架屏**：`SubjectLayout` 每次回合结束都会刷新状态快照；若刷新时提前返回占位，
  整个 `Outlet` 子树会被卸载，正在流式输出的讲解与刚到的判定卡片都会消失。
  正确做法是"已有数据就继续渲染，错误用 Banner 叠加"。
- **流式**：`useTurnStream` 里 `pendingRef` + 定时器做 60ms 合帧；`reset`、组件卸载、回合结束都要清定时器，
  且结束前必须 `flush()`。
- **文案与状态**：状态徽标文案集中在 `components/labels.ts`，不要在页面里硬编码中文状态名。
- **可访问性**：焦点环靠 `:focus-visible`（`index.css` 统一给 `a/summary/button`）；状态不能只靠颜色，
  一律带文字；窄屏断点在 820px，表格用横向滚动而不是压列宽。
- **错误提示**：用 `errorMessage()` 归一后端 `detail`，不要直接把异常对象打到界面上。

## 10. 已知的坑

都是在真机上踩过的，按"现象 → 原因 → 规避"记。

| 现象 | 原因 | 规避 |
| --- | --- | --- |
| 换了 provider 后成本估算少一半 | 空闲折扣是 DeepSeek 的计价规则，通用接口按固定价 | 计价系数从档案取（`off_peak_multiplier`），不要写死 0.5 |
| 思维链突然不显示了 | 通用档案的 `reasoning_fields` 只认 `reasoning_content`，而该服务用 `reasoning` | 两种字段名都要试（`extract_delta` 已内置） |
| 桩测试全绿但真网关 400 | 桩不校验请求体，真网关会 | 起一个"严格上游"探针（收到 `thinking` 就回 400）跑真实 HTTP，比加断言更早暴露问题 |
| PowerShell 里写中文变成 `???` 或乱码 | here-string 管道/`python -c` 传参的编码被吞 | 把脚本写进 `.py` 文件再执行；提交信息用 `[System.IO.File]::WriteAllText(..., UTF8Encoding($false))` 落文件后 `git commit -F` |
| `Invoke-WebRequest` 拿不到 4xx 响应体 | Windows PowerShell 5.1 没有 `-SkipHttpErrorCheck` | 用 `System.Net.Http.HttpClient` 或 `curl.exe` |
| pytest 输出被截断，看不到"多少通过" | PowerShell 管道截断 | 重定向到文件再 `Get-Content -Tail`；或用 `$LASTEXITCODE` 判断 |
| 复制的 `welearn.db` 少了最近的数据 | WAL 模式下已提交事务还在 `-wal` 里 | 用 `scripts/backup_db.py`（SQLite 在线备份 API） |
| 静态资源想加缓存头加不上 | `StaticFiles` 不支持按响应设 header | 用 `app/api/static_site.py` 的兜底路由 |
| 界面上"第 0 次作答" | `attempt_index` 从 0 起 | 展示时 +1 |
| dev 下从画像页跳路径页，停在空态 | StrictMode 二次挂载中止了第一次 POST，而"已自动开始"的一次性标志已被消耗 | 生产构建不受影响；端到端脚本在空态再点一次「生成学习路径」 |
| 点 Tab 断言焦点环失败，但样式确实写了 | `element.focus()` 不一定触发 `:focus-visible` | 测试里真的按 Tab 走一遍 |
| Playwright 点击/按键后滚动位置变了 | `locator.press()` 会自动滚动到元素 | 用 `page.keyboard.type()` |
| `scripts/` 里加 `__init__.py` 后测试导入报错 | `scripts/` 故意不是包，测试用 `importlib` 加载 | 不要加 `__init__.py` |
| ruff 报一堆全角标点 | `RUF001/002/003` 对中文全角标点敏感 | 已在 `pyproject.toml` 里忽略（中文文档就该用全角） |
