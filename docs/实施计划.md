### 1.3 已实现的能力

**学习主线**
- 主题：创建 / 列表（含进度、同名提示、建议复习）/ 详情 / 重命名 / 归档 / 删除（级联清理）
- 测评：子领域推导、逐轮提问、结构化画像、跳过测评；**整轮原子**，失败整体回退
- 画像：逐项手动修正（FR-207）、测评过程回放（FR-208）
- 路径：生成（含生成理由）/ 确认门禁 / 版本保留 / 单节点重生成 / 整条重生成
- 路径编辑：改标题目标要点、插入、删除、上下移动；已开始学习的节点禁止结构调整
- 教学：讲解 → 检查点提问 → 独立判定 → 重讲 → 重试耗尽后三选一 → 通过才前进
- 教学深化：三级提示（按连续失败自动升档）、穿插提问（不改状态机）、重新生成上一条
- 暂停 / 继续 / 跳过节点；跳过会记入薄弱点

**复习与档案**
- 相邻复习（进入新节点前回顾上一节点）
- 薄弱点复习：清单、一键开始、复用节点已有检查点（开局不产生模型调用）
- 间隔复习：Leitner 阶梯（1/3/7/21/60 天）、今日复习清单、久未复习提醒
- 学习档案：进度可视化、逐节点笔记（手写/自动小结分开标注）、作答历史（区分教学/复习）
- 完成报告：已掌握 / 部分掌握（带原因）/ 已跳过、薄弱点、token 与累计耗时、成本估算
- 节点历史入口：教学页侧栏与档案页共用同一份记录渲染

**模型与运维**
- 按用途的模型与思考档位（推荐组合 + 逐用途覆盖），返回只读 `model_plan`（实际生效值）
- 采样参数 `temperature` / `top_p`，并在界面上标注官方生效性约束（FR-718）
- 思维链折叠展示开关（FR-713）；请求审计开关（FR-715，Key 全程脱敏）
- 用量聚合：总量 / 按用途 / 按主题 / 缓存命中提示
- 成本估算：高峰与空闲双价（北京时间工作日 9–12、14–18 为高峰），**逐条按发生时刻计价**
- 余额查询（按币种展示；失败不影响主流程）
- 健康检查：存储与日志可写性（真写探针）、审计状态、用量摘要、特性开关
- 日志按大小轮转 + 保留期清理 + 手动清理入口；可选访问口令（只存 SHA-256）

**数据流转**
- 导出：Markdown 学习报告 / JSON 备份（含路径、笔记、作答、薄弱点与记忆正文）
- 导入：JSON 备份还原为新主题（全部 id 重新生成，可重复导入）
- 全局检索：笔记、作答、历史对话三处一起搜
- 工具调用（默认关闭）：读取档案、写入笔记、记录薄弱点；**永不下发 `tool_choice`**

## 2. 规划原则（仍然适用）

| # | 原则 | 为什么 |
| --- | --- | --- |
| 1 | **记忆 + Agent 内核先做** | 五个用途共用同一套"一轮对话"机制，是全项目最大复用点 |
| 2 | **契约先冻结再动前端** | 事件类型、结构化输出 schema、表结构未冻结就写前端必然返工 |
| 3 | **状态机早立** | 会话状态与"待回答的检查点"必须落库（FR-410），后期补做等于重构 |
| 4 | **质量风险靠实测而非猜测** | 结构化输出、判定、压缩、思考档位四项必须用真实额度先量化 |
| 5 | **失败路径与成功路径同批实现** | 失败不污染记忆、错误分类、空内容/截断都是失败路径，留到最后会撼动内核 |
| 6 | **每阶段可独立演示** | 阶段结束必须能在 UI 或日志上看到实质进展 |
| 7 | **写路径必须有端到端验证** | 只跑构建与只读接口抓不出"编辑被静默丢弃"这类问题（详见实施记录 §4.5） |

## 3. 当前代码地图

```text
app/
  main.py              # 应用装配、路由注册、访问口令中间件
  main_context.py      # 依赖容器：路径/数据库/设置/密钥/日志/LLM 客户端/用途策略
  api/                 # 路由层（无业务逻辑）
    subjects.py        # 主题、测评、路径、教学、复习、档案、报告（含 SSE 端点）
    settings.py        # 设置、API Key、模型列表、用量聚合
    health.py          # 健康检查
    billing.py         # 余额
    exports.py         # 导出 / 导入
    search.py          # 全局检索
    ops.py             # 日志统计与清理、口令探针
    sse.py / deps.py / serializers.py
  contracts/           # 冻结契约：SSE 事件 + 结构化输出 schema
  services/
    learning/          # 领域编排：subjects / state / assessment / planning / teaching
                       # / review / schedule / export / search / repository / stack
    llm/               # memory / repository / agent / dispatcher / policy / structured
                       # / judge / compression / context_policy / usage / cost / tools
  infra/
    paths.py / redaction.py / secrets.py / settings.py / access.py
    storage/           # db.py（版本与列级升级）、models.py
    logging/           # queue_logger.py（异步写入、轮转、清理）
    deepseek/          # client.py、sse.py、protocol.py、errors.py
  prompts/             # 提示词装配（统一追加安全约束）

web/src/
  api/                 # types / client（含口令头）/ sse / endpoints
  hooks/               # useTurnStream（流式回合）、useResource（只读加载）
  components/          # Conversation / Markdown / Banner / StatusBadge
                       # / NodeHistoryPanel / AuthPrompt
  pages/               # Subjects / NewSubject / Assessment / Path / Teaching
                       # / Review / Archive / Search / Settings
  utils/download.ts    # Blob 下载

scripts/
  dev_stub_server.py   # 假 LLM 服务端（隔离栈联调与端到端验证）
  spike_real.py        # 真实额度抽样工具
tests/                 # 单测 + 桩 + 夹具；recorded/ 为真实响应样本
```

**分层约束**：`api/` 不写业务逻辑（只做校验、序列化、错误映射）；`services/learning/` 管领域流程；
`services/llm/` 管模型调用与记忆；`infra/` 只提供设施。跨层调用一律经由 `LearningStack`。

## 7. 验证策略

| 层次 | 手段 | 覆盖范围 |
| --- | --- | --- |
| 单元测试 | pytest + 注入桩 LLM | 状态机、判定解析、压缩签名校验、路径生成解析、配置回退、路径越界、SSE 解析、成本计价 |
| 契约测试 | 用 `recorded/` 的真实响应夹具回放 | 空 `content`、截断 JSON、429、`: keep-alive`、连接关闭；同时充当官方结构变化哨兵 |
| 集成测试 | 本地空跑（不调真实 API）+ 假 SSE 服务 | 一轮对话、工具调用累积、压缩后台执行、完整 HTTP 闭环 |
| 端到端 | 隔离栈（`dev_stub_server.py` + vite 另开端口）+ 真实浏览器 | 复习闭环、档案页、设置写路径、导入导出、访问口令 |
| 全量回归 | P5 按 AC-01~AC-33 逐条执行 | 交付验收 |

**成本控制**：日常开发默认使用桩与夹具；仅在对模型行为有疑问时使用真实额度，并开启用量统计观察。

**前端验证约定**：`web/` 没有测试框架，视觉与交互改动靠真实浏览器验证；
所有写入类改动必须改一次并读回，不能只看构建通过。

## 8. 风险与应对

| 优先级 | 风险 | 影响 | 应对 |
| --- | --- | --- | --- |
| 1 | 判定"放水"导致门禁失效 | 教学效果失真，核心价值受损 | 判定独立调用；强制枚举 + 要求列出命中要点；`pass` 必须带命中要点，否则降级 |
| 2 | 结构化输出不稳定（空内容 / 截断） | 流程中断 | 满足 JSON Output 前置条件；空内容与截断各重试一次；正文为空绝不入库 |
| 3 | 压缩正确性缺陷 | 静默污染后续全部对话 | 内容指纹校验是硬要求（FR-606）；离线测试覆盖"压缩期间新增轮次" |
| 4 | 上下文与费用膨胀 | 成本超预期、响应变慢 | 按用途配置思考档位；缓存友好（前缀稳定）；用量与成本可视化 |
| 5 | 单节点反复重讲导致"卡死" | 挫败感 | 重试上限 + 分级提示 + 三选一出口 |
| 6 | 官方接口 / 参数 / 价格变更 | 功能或费用异常 | 模型与单价可配置；`GET /models` 动态元数据；错误分类提示 |
| 7 | 交付形态与真实环境不一致 | 用户装不起来 | T5.1 用干净环境验证；T5.5 做备份恢复与升级迁移演练 |

## 10. 当前遗留与技术债

| 项 | 说明 | 计划 |
| --- | --- | --- |
| 路径页"自动生成"在 dev 下不触发 | 从画像页/新建页带 `state.generate` 跳转时，dev 下 StrictMode 二次挂载会中止第一次 POST，而"已自动开始过"的一次性标志已被消耗 → 停在空态。生产构建不受影响，用户再点一次「生成学习路径」即可 | P5 评估（修法有"重复生成两个版本"的风险） |
| 工具轮的用量按"轮"合并落库 | 一轮内多次模型请求（工具轮 + 正文轮）合并为一条用量记录：token 准确，但 `calls` 少计中间调用 | P5 评估是否拆为逐请求 |
| 法定节假日未按空闲计价 | FR-706 要求"含法定节假日为空闲"，当前只按周末判断，未内置节假日历 | P5 可选 |
| 导入不恢复进行中的会话 | 备份恢复路径/笔记/作答/薄弱点与记忆正文，但不恢复"正停在哪个节点、待答哪个检查点" | 按需 |
| 前端无测试框架 | 视觉与交互依赖真实浏览器验证，写入类改动需人工走查 | 维持现状（已写入 DoD 第 7 条） |
