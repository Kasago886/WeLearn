### 1.3 已实现的能力

**学习主线**
- 主题：创建 / 列表（含进度、同名提示、建议复习）/ 详情 / 重命名 / 归档 / 删除（级联清理）
- 测评：子领域推导、逐轮提问、结构化画像、跳过测评；**整轮原子**，失败整体回退
- 画像：逐项手动修正（FR-207）、测评过程回放（FR-208）
- 路径：生成（含生成理由）/ 确认门禁 / 版本保留 / 单节点重生成 / 整条重生成
- 路径编辑：改标题目标要点、插入、删除、上下移动；已开始学习的节点禁止结构调整
- 教学：讲解 → 检查点提问 → 独立判定 → 重讲 → 重试耗尽后三选一 → 通过才前进
- 教学深化：三级提示（按连续失败自动升档）、穿插提问（不改状态机）、重新生成上一条
- 暂停 / 继续 / 跳过节点；跳过会记入薄弱点

**复习与档案**
- 相邻复习（进入新节点前回顾上一节点）
- 薄弱点复习：清单、一键开始、复用节点已有检查点（开局不产生模型调用）
- 间隔复习：Leitner 阶梯（1/3/7/21/60 天）、今日复习清单、久未复习提醒
- 学习档案：进度可视化、逐节点笔记（手写/自动小结分开标注）、作答历史（区分教学/复习）
- 完成报告：已掌握 / 部分掌握（带原因）/ 已跳过、薄弱点、token 与累计耗时、成本估算
- 节点历史入口：教学页侧栏与档案页共用同一份记录渲染

**模型与运维**
- 接口类型可选：`deepseek`（默认，含思考开关、缓存统计、余额、空闲半价）与 `openai`（通用 OpenAI 兼容）
- 参数不被接受时自动降级重发（`reasoning_effort` / `response_format` / `thinking` / `max_tokens` 别名）
- 按用途的模型与思考档位（推荐组合 + 逐用途覆盖），返回只读 `model_plan`（实际生效值）
- 采样参数 `temperature` / `top_p`，并在界面上标注官方生效性约束（FR-718）
- 思维链折叠展示开关（FR-713）；请求审计开关（FR-715，Key 全程脱敏）
- 用量聚合：总量 / 按用途 / 按主题 / 缓存命中提示
- 成本估算：高峰与空闲双价（北京时间工作日 9–12、14–18 为高峰），**逐条按发生时刻计价**
- 余额查询（按币种展示；失败不影响主流程）
- 健康检查：存储与日志可写性（真写探针）、审计状态、用量摘要、特性开关
- 日志按大小轮转 + 保留期清理 + 手动清理入口；可选访问口令（只存 SHA-256）

**数据流转**
- 导出：Markdown 学习报告 / JSON 备份（含路径、笔记、作答、薄弱点与记忆正文）
- 导入：JSON 备份还原为新主题（全部 id 重新生成，可重复导入）
- 全局检索：笔记、作答、历史对话三处一起搜
- 工具调用（默认关闭）：读取档案、写入笔记、记录薄弱点；**永不下发 `tool_choice`**

**交付与运维**
- 交付形态：单一 Python 进程同时提供接口与前端产物（`web/dist`），或 `docker compose up` 一键起容器
- 备份：`scripts/backup_db.py` 在线备份 / 校验 / 恢复（SQLite 备份 API，含 WAL 已提交内容）
- 升级：启动时按 `SCHEMA_VERSION` 幂等升级，老库原地迁移
- 性能：`scripts/perf_check.py` 量首 token 延迟与本地接口 p50/p95；前端流式渲染按 60ms 节流
- 可用性：统一焦点环、窄屏（≤820px）单列布局、`prefers-reduced-motion` 降级

## 2. 规划原则（仍然适用）

| # | 原则 | 为什么 |
| --- | --- | --- |
| 1 | **记忆 + Agent 内核先做** | 五个用途共用同一套"一轮对话"机制，是全项目最大复用点 |
| 2 | **契约先冻结再动前端** | 事件类型、结构化输出 schema、表结构未冻结就写前端必然返工 |
| 3 | **状态机早立** | 会话状态与"待回答的检查点"必须落库（FR-410），后期补做等于重构 |
| 4 | **质量风险靠实测而非猜测** | 结构化输出、判定、压缩、思考档位四项必须用真实额度先量化 |
| 5 | **失败路径与成功路径同批实现** | 失败不污染记忆、错误分类、空内容/截断都是失败路径，留到最后会撼动内核 |
| 6 | **每阶段可独立演示** | 阶段结束必须能在 UI 或日志上看到实质进展 |
| 7 | **写路径必须有端到端验证** | 只跑构建与只读接口抓不出"编辑被静默丢弃"这类问题（详见实施记录 §4.5） |

### 4.1 P6 接入层通用化（2026-11-02）

一次纯接入层改动：协议本来就是 OpenAI 兼容的，问题在于**参数与解析写死了 DeepSeek 的口径**。
把差异集中进供应商档案后，同一份代码既能连 DeepSeek，也能连任意 OpenAI 兼容服务。

| 改动 | 内容 |
| --- | --- |
| 能力档案 | `app/infra/llm/providers.py`：`openai` / `deepseek` 两份档案，描述请求字段、思维链字段名、缓存字段形状、余额接口、空闲折扣、是否回传思维链 |
| 协议层 | `build_chat_request` / `extract_delta` / `TokenUsage.from_usage_dict` / `parse_blocking_response` 均按档案分流；不传档案时按 DeepSeek 处理（既有调用方零改动） |
| 客户端 | `DeepSeekClient` → `LlmClient`，新增 `provider_getter`；参数被拒时自动降级重发一次 |
| 设置 | 新增 `provider`（默认 `deepseek`）、只读 `provider_capabilities` / `provider_options` / `env_overridden`；`WELEARN_PROVIDER` 环境变量 |
| 计价 | 空闲折扣随档案走：非 DeepSeek 接口按固定价结算（否则金额少一半） |
| 前端 | 设置页「接口类型」下拉；切换时按能力改写提示、灰掉余额按钮；环境变量覆盖时给出明确提示 |
| 表结构 | v8：`app_settings.provider`（留空即默认，老库无需回填） |

**出口条件**：两种档案各自的请求/响应行为有测试；`/api/settings`、`/api/health`、`/api/balance`
按接口类型给出正确结果；老库升级后行为不变；真实 HTTP（严格上游）验证通过。

## 8. 风险与应对

| 优先级 | 风险 | 影响 | 应对 |
| --- | --- | --- | --- |
| 1 | 判定"放水"导致门禁失效 | 教学效果失真，核心价值受损 | 判定独立调用；强制枚举 + 要求列出命中要点；`pass` 必须带命中要点，否则降级 |
| 2 | 结构化输出不稳定（空内容 / 截断） | 流程中断 | 满足 JSON Output 前置条件；空内容与截断各重试一次；正文为空绝不入库 |
| 3 | 压缩正确性缺陷 | 静默污染后续全部对话 | 内容指纹校验是硬要求（FR-606）；离线测试覆盖"压缩期间新增轮次" |
| 4 | 上下文与费用膨胀 | 成本超预期、响应变慢 | 按用途配置思考档位；缓存友好（前缀稳定）；用量与成本可视化 |
| 5 | 单节点反复重讲导致"卡死" | 挫败感 | 重试上限 + 分级提示 + 三选一出口 |
| 6 | 官方接口 / 参数 / 价格变更 | 功能或费用异常 | 模型与单价可配置；`GET /models` 动态元数据；错误分类提示 |
| 7 | 交付形态与真实环境不一致 | 用户装不起来 | T5.1 用干净环境验证；T5.5 做备份恢复与升级迁移演练 |

## 10. 当前遗留与技术债

| 项 | 说明 | 处置 |
| --- | --- | --- |
| Docker 未在本机实跑 | 开发机没有 Docker，`docker compose up` 未实测。已做的替代验证：compose YAML 可解析、Dockerfile 引用文件齐全、`pip` 打包含 13 个提示词模板、按镜像布局（`app/` + `web/dist` 同目录、非仓库根路径）起真实进程并通过 SPA/接口/缓存头冒烟 | 首次部署时按 README 走一遍；若失败优先看 `./data` 属主与端口占用 |
| 路径页"自动生成"在 dev 下不触发 | 从画像页/新建页带 `state.generate` 跳转时，dev 下 StrictMode 二次挂载会中止第一次 POST，而"已自动开始过"的一次性标志已被消耗 → 停在空态。生产构建不受影响，用户再点一次「生成学习路径」即可 | 不修（修法有"重复生成两个版本"的风险），仅影响开发期 |
| 工具轮的用量按"轮"合并落库 | 一轮内多次模型请求（工具轮 + 正文轮）合并为一条用量记录：token 准确，但 `calls` 少计中间调用 | 接受（token 与成本口径正确） |
| 法定节假日未按空闲计价 | FR-706 要求"含法定节假日为空闲"，当前只按周末判断，未内置节假日历 | 接受（周末已覆盖大部分低峰），需要时补节假日表 |
| 导入不恢复进行中的会话 | 备份恢复路径/笔记/作答/薄弱点与记忆正文，但不恢复"正停在哪个节点、待答哪个检查点" | 接受（导入语义是"新建主题"） |
| 前端无测试框架 | 视觉与交互依赖真实浏览器验证，写入类改动需人工走查 | 维持现状（已写入 DoD 第 7 条） |
