## 1. 下行事件契约（后端 → 前端）

传输：`text/event-stream`，每帧形如

```text
event: token
data: {"text":"北"}
```

| 事件 | 载荷字段 | 发送时机 | 关联需求 |
| --- | --- | --- | --- |
| `token` | `text` | 正文增量（流式，可多次） | FR-401, FR-412 |
| `reasoning` | `text` | 思维链增量（流式，前端默认折叠，可通过 `show_reasoning` 关闭） | FR-713 |
| `verdict` | `verdict` / `confidence` / `feedback` / `missing_points` | 检查点判定完成 | FR-404 |
| `node_state` | `node_id` / `state` / `index` / `total` | 节点状态变更 | FR-309, FR-408 |
| `error` | `category` / `message` / `retryable` | 出现可操作错误 | FR-709, FR-712 |
| `done` | `conversation_id` / `usage` | 一轮结束（含用量） | FR-705 |

`verdict` 取值：`pass` / `partial` / `fail`。
`node_state` 取值：`not_started` / `learning` / `mastered` / `partial` / `skipped` / `review_needed`。

**前端必须遵守的两条约定**：

1. `error` 的 `message` 是**面向用户的可操作文案**，不得显示原始异常或响应体；
2. `done` 之后本轮结束，客户端不得再等待更多事件；`retryable=true` 的错误才展示"重试"入口。

对应代码：`app/contracts/events.py`（`SseEventType`、各 payload 模型、`encode_frame`）。

## 2. 结构化输出契约（模型 → 后端）

统一要求（FR-716）：

1. 请求设置 `response_format = {"type":"json_object"}`；
2. 提示词中**必须出现 `json` 字样**并给出输出样例；
3. **必须显式设置 `max_tokens`**，否则 JSON 可能被截断；
4. 必须处理官方已知的"返回空 `content`"：解析失败或为空时重试一次，重试仍失败给出可重试错误，且不得污染会话状态。

| 用途 | JSON 结构（摘要） | 硬约束（违反即构造失败） | 关联需求 |
| --- | --- | --- | --- |
| 测评画像 | `{"levels":[{"topic","level","evidence"}],"summary","suggested_start_node"}` | `level ∈ {none,basic,proficient}`；`levels` 1~12 项 | FR-206 |
| 路径规划 | `{"rationale","nodes":[{"title","objective","prerequisites","key_points","checkpoints":[{"question","expected_points","reference_answer"}]}]}` | `nodes` 3~15 个；每个节点 `key_points` 3~6 条、`checkpoints` ≥1 个且 `expected_points` 非空 | FR-301, FR-302 |
| 判定 | `{"verdict","confidence","feedback","missing_points"}` | `verdict ∈ {pass,partial,fail}`；`confidence ∈ [0,1]` | FR-404 |
| 压缩摘要 | `{"compressed_context":"..."}` | 空串表示无需保留（`Empty`，不重试） | FR-605, FR-607 |

对应代码：`app/contracts/schemas.py`。解析容错规则见需求规格说明书 FR-607（严格 JSON → 去 markdown 包裹 → 截取最外层 `{}`）。

## 3. 上游请求契约（后端 → DeepSeek）

端点：`POST {base_url}/chat/completions`；`base_url` 保留子路径（如 `/v1`）。

| 字段 | 取值 | 说明 |
| --- | --- | --- |
| `model` | `deepseek-flash`（默认）/ `deepseek-v4-pro` | 旧名 `deepseek-v4-flash`、`deepseek-v4-flash-vision-exp` 仍可调用，但官方会映射到 DeepSeek-V4.1-Flash 并按 Flash 计价（FR-702） |
| `messages` | 协议消息数组 | 消息以原始字段字典承载，保留服务端附加字段（FR-603） |
| `stream` | `true` / `false` | 流式用于教学与测评 |
| `thinking` | `{"type":"enabled"｜"disabled"}` | 官方默认开启（FR-717） |
| `reasoning_effort` | `low` / `high` / `max` | 仅思考开启时下发；官方默认 `high` |
| `max_tokens` | 正整数 | JSON Output 场景必须下发（FR-716） |
| `response_format` | `{"type":"json_object"}` | 仅结构化输出场景下发 |
| `tools` | 工具数组 | **仅在确有工具时下发**，避免部分端点不接受 `"tools": null` |

**官方限制（由上层保证）**：思考模式下不支持 `tool_choice=required` 与指定具体 tool（返回 400，FR-714）；
思考模式下 `temperature`/`presence_penalty`/`frequency_penalty` 不生效、`top_p` 被钳制到 `0.95`–`1.0`（FR-718）；
携带 `tools` 时历史 `reasoning_content` 必须回传并会拼进上下文（FR-719）。

对应代码：`app/infra/deepseek/protocol.py`。

## 4. 错误分类契约

| 状态码 / 情形 | `category` | 可重试 | 面向用户的提示 |
| --- | --- | --- | --- |
| 400 | `bad_request` | 否 | 请求体格式错误，请检查模型名与消息结构后重试。 |
| 401 | `auth` | 否 | API Key 无效或未授权，请在设置中更新 Key。 |
| 402 | `balance` | 否 | 账户余额不足，请充值后重试。 |
| 422 | `invalid_params` | 否 | 请求参数错误，请检查模型名与参数取值。 |
| 429 | `rate_limit` | 是 | 请求速率达到上限，稍后会自动重试。 |
| 500 | `server_error` | 是 | DeepSeek 服务器故障，稍后会自动重试。 |
| 503 | `unavailable` | 是 | DeepSeek 服务器繁忙，稍后会自动重试。 |
| 超时 | `timeout` | 是 | 请求超时，可点击重试或调大超时时间。 |
| 网络中断 / 服务端在 10 分钟未开始推理时关闭连接 | `network` | 是 | 网络连接中断，请检查网络后重试。 |
| 配置缺失（未配 Key / base_url / model） | `config` | 否 | 按缺失项给出具体引导 |
| 响应结构不符 | `protocol` | 否 | 响应无法解析，请查看日志 |

**重试边界**：仅在尚未产出任何增量时重试，默认最多 2 次、指数退避；
一旦已向前端吐出内容，失败直接上报（FR-412），避免重复内容。

对应代码：`app/infra/deepseek/errors.py`、`app/infra/deepseek/client.py`。

## 5. 数据库表结构

时间戳统一存 UTC（展示时转本地）。已落地（T0.3）：

| 表 | 主键 | 关键列 | 说明 |
| --- | --- | --- | --- |
| `schema_version` | `version` | `applied_at` | 轻量迁移记录（见待决策项 E2） |
| `app_settings` | `id`（恒 1） | 全部业务列可空 | 列缺失/非法即回退默认（FR-902） |
| `api_key_secret` | `id`（恒 1） | `cipher`、`masked_hint`、`source` | 只存密文（FR-708） |
| `conversation` | `id`（uuid） | `kind`、`subject_id`、`round_count`、`compressed_at` | 记忆容器，测评/教学/复习各一条（FR-602） |
| `chat_round` | `id` | `conversation_id`、`round_index` | 唯一索引 `(conversation_id, round_index)` |
| `message` | `id` | `role`、`content`、`reasoning_content`、`tool_calls_json`、`is_summary` | 摘要消息标记 `is_summary` |
| `usage_record` | `id` | `purpose`、`model`、`prompt/cached/miss/completion/reasoning/total tokens` | 命中与未命中都记录（FR-705） |

**P2 待落地的领域表**（字段见需求规格说明书第 6 章，届时补入 `app/infra/storage/models.py`）：
`subject`、`session_state`、`assessment`、`assessment_level`、`learning_path`、`knowledge_point`、
`checkpoint`、`answer_record`、`weak_point`、`study_note`。

> 说明：`conversation.subject_id`、`usage_record.subject_id`/`conversation_id` 暂用字符串外键，
> 待 `subject` 表落地后再补外键约束，避免"先建表后改约束"的迁移负担。

## 6. HTTP 接口（当前仅有冒烟端点）

`GET /api/health`（FR-909 的最小版本，T3.6 在保持字段兼容的前提下扩展）：

```json
{
  "status": "ok | degraded",
  "problems": ["storage", "api_key"],
  "storage": { "ok": true, "detail": "ok", "data_dir": "...", "schema_version": 1 },
  "model": { "base_url": "...", "default": "deepseek-flash", "pro": "deepseek-v4-pro",
             "thinking_enabled": true, "reasoning_effort": "high",
             "max_tokens": 8192, "timeout_seconds": 60 },
  "api_key": { "configured": false, "source": "none | env | db", "masked": null },
  "logging": { "level": "INFO", "log_dir": "..." }
}
```

约定：**响应中永不含 API Key 明文或密文**；存储或密钥读取失败时返回 200 且 `status = degraded`，
并在 `problems` 中标出原因（NFR-107）。

## 8. 真实样本验证结论（2026-10-10 录制）

录制命令：`python scripts/llm_smoke.py --record`（模型 `deepseek-flash`，思考开启，`effort=high`）。
回放测试见 `tests/test_recorded_fixtures.py`。以下为实测确认的事实，实现已与之对齐：

| # | 实测事实 | 对实现的影响 |
| --- | --- | --- |
| 1 | 数据块除 `choices` 外还带 `object` / `created` / `system_fingerprint`，`choices[0]` 还带 `logprobs` | 解析器只读 `choices[0].delta`，必须忽略未知字段（已满足） |
| 2 | 首块 `delta` 为 `{role:"assistant", content:null, reasoning_content:""}`，后续块也会出现空串 | 空串必须按"无增量"丢弃，否则会向前端推大量空事件（已满足） |
| 3 | 思维链与正文在 `delta` 中**交替**到达（本次 235 个思维链碎片、92 个正文碎片） | 前端需分别渲染两路增量；`reasoning` 与 `token` 事件不可合并 |
| 4 | 用量只在最后一个数据块出现：`prompt=40, cached=0, miss=40, completion=328, reasoning=235, total=368` | 收尾事件 `done` 必须携带该用量；首次调用的 `cached=0` 属正常（尚无缓存前缀） |
| 5 | JSON Output 返回 `{"answer": "..."}`，可用 `json.loads` 直接解析；关闭思考时 `reasoning_content` 为空串 | 结构化输出通道可行；空思维链按 `None` 处理 |
| 6 | `GET /models` 返回 `deepseek-flash`（DeepSeek-V4.1-Flash）与 `deepseek-v4-pro`，`context_window=1048576`、`max_output_tokens=393216`、`effort.supported_levels=[low,high,max]`、`default_level=high` | 与官方文档一致；设置页可据此渲染档位，不必写死（FR-702、FR-717） |
| 7 | `GET /user/balance` 返回 `is_available` 与 `balance_infos[]`，**金额是字符串**（如 `"17.39"`），币种为 `CNY` | FR-710 必须按字符串解析并按币种展示，不能强转数字 |
| 8 | 本次响应较快，**未出现** `: keep-alive` 保活注释 | 保活仍按官方文档实现（忽略注释行），由 `stream_keepalive_and_broken.sse` 覆盖该形态 |

**重新录制时**：`recorded/` 内容会被覆盖，`tests/test_recorded_fixtures.py` 中的结构性断言
（可用量恒等式、思维链非空等）应继续成立；若官方响应结构发生变化，该文件会首先失败，
这正是它作为"生产结构哨兵"的价值。
