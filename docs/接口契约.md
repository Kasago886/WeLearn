## 1. 下行事件契约（后端 → 前端）

传输：`text/event-stream`，每帧形如

```text
event: token
data: {"text":"北"}
```

| 事件 | 载荷字段 | 发送时机 | 关联需求 |
| --- | --- | --- | --- |
| `token` | `text` | 正文增量（流式，可多次） | FR-401, FR-412 |
| `reasoning` | `text` | 思维链增量（流式，前端默认折叠，可通过 `show_reasoning` 关闭） | FR-713 |
| `verdict` | `verdict` / `confidence` / `feedback` / `hit_points` / `missing_points` | 检查点判定完成 | FR-404 |
| `node_state` | `node_id` / `state` / `index` / `total` | 节点状态变更 | FR-309, FR-408 |
| `assessment` | `status` / `topics` / `turn_number` / `total_turns` / `current_topic` / `profile` | 测评一次交互结束（首问、后续提问、画像、跳过） | FR-201, FR-202, FR-205, FR-206 |
| `path` | `path_id` / `version` / `rationale` / `nodes[]` | 学习路径生成完成 | FR-301, FR-308 |
| `options` | `kind` / `choices` / `message` / `directions` | 需要用户做出选择（重试耗尽后的三选一） | FR-408 |
| `hint` | `level` / `label` / `question` | 给出了一级提示 | FR-407 |
| `error` | `category` / `message` / `retryable` | 出现可操作错误 | FR-709, FR-712 |
| `done` | `conversation_id` / `usage` | 一轮结束（含用量） | FR-705 |

**取值约束**

- `verdict`：`pass` / `partial` / `fail`
- `node_state.state`：`not_started` / `learning` / `mastered` / `partial` / `skipped` / `review_needed`
- `assessment.status`：`question`（提问）/ `profile`（画像已产出）/ `skipped`（用户跳过测评）
- `options.kind`：`exhausted`（单节点重试已耗尽，三项选择 `reteach` / `show_answer` / `advance`）
- `hint.level`：`1`（方向性）/ `2`（关键要素）/ `3`（近似答案）；`hint.label` 是对应的中文名，
  前端直接展示即可，不必自己维护映射表

**`path` 事件里的 `nodes[]`**：`id` / `index` / `title` / `objective` / `key_points` / `state` /
`is_quick_review` / `checkpoints[]`（`id` / `question`）。`rationale` 是"为什么这样安排"的说明，
必须在路径页展示（FR-302）。

**`assessment` 事件的 `profile`**（仅当 `status = profile` 时非 `null`）：`levels[]`
（`topic` / `level` / `evidence`）/ `summary` / `suggested_start_node`。

### 1.1 节点位置约定

`node_state.index`、路径里 `nodes[].index`、`current_index` **一律从 1 开始**，
与 UI 上的"第 2/4 个节点"一致；需要 0 基下标时请用数组顺序，不要用这些字段减一。
`total` 为路径节点总数。`current_index` 指向第一个尚未完成的节点，全部完成时指向最后一个节点
（是否真正完成以 `completed` 为准）。

`node_state` 描述的是**本轮结束时用户所在的节点**：进入节点时为 `learning`（FR-309）、
判定通过为 `mastered`、重试耗尽后选择"查看参考答案"为 `partial`、
选择"直接进入下一节点"则报出**下一个节点**（`not_started`，会话同时落到该节点上）。

### 1.2 刷新恢复的数据来源

前端刷新后不需要自己拼状态，契约里已经给了三份数据：

| 场景 | 恢复依据 |
| --- | --- |
| 该显示哪一步 | `GET /state` 的 `session.next_action`（`assess` / `confirm_path` / `teach` / `answer` / `decide` / `completed` / `paused`） |
| 测评中：正在问什么 | `GET /assessment` 的 `transcript` + `pending_question`（`pending_question` 仅在测评进行中非空） |
| 教学中：问过什么、判过什么 | `GET /teach/current` 的 `pending_question` + `answers`（`answer_record` 全量记录） |

**为什么教学的讲解正文不在恢复范围内**：它存在于对话记忆里、可以被重新生成，
而作答记录是用户自己的输入，丢了就找不回来——恢复的优先级按"不可再生"排序。

### 1.3 前端必须遵守的两条约定

1. `error` 的 `message` 是**面向用户的可操作文案**，不得显示原始异常或响应体；
2. `done` 之后本轮结束，客户端不得再等待更多事件；`retryable=true` 的错误才展示"重试"入口。

### 1.4 错误分类（`error.category` 取值）

`busy`（正在生成，AC-17）、`config`、`auth`、`balance`、`rate_limit`、`server_error`、
`unavailable`、`timeout`、`network`、`bad_request`、`invalid_params`、`protocol`、
`empty_content`、`unknown`。

其中 `busy` 由后端调度器产生（FR-611：明确拒绝而非静默丢弃）。

### 1.5 判定降级语义

若模型把 `verdict` 判为 `pass` 却未给出 `hit_points`（或同时给出 `missing_points`），
后端会**自动降级为 `partial`** 并在 `feedback` 末尾追加说明（FR-404）。
前端无需感知该逻辑，但不得假定"模型说 pass 就一定收到 pass"。

`hit_points` 是必填可见字段：`pass` 的依据必须可见，否则无法发现"放水"。

对应代码：`app/contracts/events.py`（`SseEventType`、各 payload 模型、`encode_frame`）。

## 2. 结构化输出契约（模型 → 后端）

统一要求（FR-716）：

1. 请求设置 `response_format = {"type":"json_object"}`；
2. 提示词中**必须出现 `json` 字样**并给出输出样例；
3. **必须显式设置 `max_tokens`**，否则 JSON 可能被截断；
4. 必须处理官方已知的"返回空 `content`"：解析失败或为空时重试一次，重试仍失败给出可重试错误，
   且不得污染会话状态。

| 用途 | JSON 结构（摘要） | 硬约束（违反即构造失败） | 关联需求 |
| --- | --- | --- | --- |
| 测评画像 | `{"levels":[{"topic","level","evidence"}],"summary","suggested_start_node"}` | `level ∈ {none,basic,proficient}`；`levels` 1~12 项 | FR-206 |
| 路径规划 | `{"rationale","nodes":[{"title","objective","prerequisites","key_points","checkpoints":[{"question","expected_points","reference_answer"}]}]}` | `nodes` 3~15 个；每个节点 `key_points` 3~6 条、`checkpoints` ≥1 个且 `expected_points` 非空 | FR-301, FR-302 |
| 判定 | `{"verdict","confidence","feedback","hit_points","missing_points"}` | `verdict ∈ {pass,partial,fail}`；`confidence ∈ [0,1]`；**`pass` 必须给出非空 `hit_points`**，否则判定器自动降级为 `partial` | FR-404, FR-405 |
| 压缩摘要 | `{"compressed_context":"..."}` | 空串表示无需保留（`Empty`，不重试） | FR-605, FR-607 |

**解析容错顺序**（FR-607）：严格 JSON → 去 markdown 包裹 → 截取最外层 `{}`。

对应代码：`app/contracts/schemas.py`。

## 3. 上游请求契约（后端 → DeepSeek）

端点：`POST {base_url}/chat/completions`；`base_url` 保留子路径（如 `/v1`）。

| 字段 | 取值 | 说明 |
| --- | --- | --- |
| `model` | `deepseek-flash`（默认）/ `deepseek-v4-pro` | 旧名 `deepseek-v4-flash`、`deepseek-v4-flash-vision-exp` 仍可调用，但官方会映射到 DeepSeek-V4.1-Flash 并按 Flash 计价（FR-702） |
| `messages` | 协议消息数组 | 消息以原始字段字典承载，保留服务端附加字段（FR-603） |
| `stream` | `true` / `false` | 流式用于教学与测评 |
| `thinking` | `{"type":"enabled"｜"disabled"}` | 官方默认开启（FR-717） |
| `reasoning_effort` | `low` / `high` / `max` | 仅思考开启时下发；官方默认 `high` |
| `max_tokens` | 正整数 | JSON Output 场景必须下发（FR-716） |
| `temperature` | 0~2（默认 1.0） | 采样温度（FR-718）；思考模式下官方忽略 |
| `top_p` | 0.01~1（默认 1.0） | 核采样（FR-718）；仅思考模式生效，且被钳制到 `0.95`–`1.0` |
| `response_format` | `{"type":"json_object"}` | 仅结构化输出场景下发 |
| `tools` | 工具数组 | **仅在确有工具时下发**，避免部分端点不接受 `"tools": null` |

**官方限制（由上层保证）**

- 思考模式下**不支持** `tool_choice=required` 与指定具体 tool（返回 400，FR-714）
  → 本项目**永不下发 `tool_choice`**；
- 思考模式下 `temperature` / `presence_penalty` / `frequency_penalty` 不生效、
  `top_p` 被钳制到 `0.95`–`1.0`（FR-718）。本项目不下发 `presence_penalty` / `frequency_penalty`；
- 携带 `tools` 时历史 `reasoning_content` 必须回传并会拼进上下文（FR-719）。

### 3.1 响应解析约定

这些是官方响应的既定形态，解析器与前端都按此实现（录制证据见
[变更记录 §4](接口契约变更记录.md)）：

| 约定 | 说明 |
| --- | --- |
| 忽略未知字段 | 数据块含 `object` / `created` / `system_fingerprint`，`choices[0]` 含 `logprobs`；只读 `choices[0].delta` |
| 空增量丢弃 | 首块 `delta` 可能是 `{role:"assistant", content:null, reasoning_content:""}`；空串按"无增量"处理，不得向前端推空事件 |
| 两路增量不可合并 | 思维链与正文在 `delta` 中交替到达，分别映射到 `reasoning` 与 `token` |
| 用量只在收尾块 | `done` 必须携带该用量；首次调用 `cached=0` 属正常（尚无缓存前缀） |
| 余额是字符串 | `balance_infos[]` 的金额为字符串（如 `"17.39"`），不得强转数字（FR-710） |
| 模型元数据以接口为准 | `/models` 给出上下文窗口、输出上限与 effort 档位，不写死在代码里（FR-702、FR-717） |

对应代码：`app/infra/deepseek/protocol.py`、`app/infra/deepseek/sse.py`。

## 4. 错误分类契约

| 状态码 / 情形 | `category` | 可重试 | 面向用户的提示 |
| --- | --- | --- | --- |
| 400 | `bad_request` | 否 | 请求体格式错误，请检查模型名与消息结构后重试。 |
| 401 | `auth` | 否 | API Key 无效或未授权，请在设置中更新 Key。 |
| 402 | `balance` | 否 | 账户余额不足，请充值后重试。 |
| 422 | `invalid_params` | 否 | 请求参数错误，请检查模型名与参数取值。 |
| 429 | `rate_limit` | 是 | 请求速率达到上限，稍后会自动重试。 |
| 500 | `server_error` | 是 | DeepSeek 服务器故障，稍后会自动重试。 |
| 503 | `unavailable` | 是 | DeepSeek 服务器繁忙，稍后会自动重试。 |
| 超时 | `timeout` | 是 | 请求超时，可点击重试或调大超时时间。 |
| 网络中断 / 服务端在 10 分钟未开始推理时关闭连接 | `network` | 是 | 网络连接中断，请检查网络后重试。 |
| 配置缺失（未配 Key / base_url / model） | `config` | 否 | 按缺失项给出具体引导 |
| 响应结构不符 | `protocol` | 否 | 响应无法解析，请查看日志 |
| 模型只输出思维链、正文为空 | `empty_content` | 是 | 模型这次只给出了思考过程、没有给出正文，已自动重试。请再点一次。 |

**重试边界**：默认最多 2 次、指数退避，分两种情况。

- **吐过正文再失败 → 直接上报**（FR-412）：重试会让同一段话在界面上出现两次；
- **一个字正文都没吐出来 → 允许重试**，包括"只有思维链、正文为空"的静默失败。

**`empty_content` 的两条防线**

1. 客户端在整条流没有任何正文时按可重试错误处理（**思维链不算正文**，它不是用户要的答案）；
2. 执行器在组装后的正文为空（含只有空白）时**绝不下库**，返回可重试失败。

`empty_content` 与 `protocol` 的区别：前者是"模型自己没说话"，后者是"响应结构对不上"。
结构化输出通道（§2）对空内容的处理更早：会把 `max_tokens` 翻倍后重试一次，
因此 JSON 场景下这条链路通常不会冒到用户面前。

对应代码：`app/infra/deepseek/errors.py`、`app/infra/deepseek/client.py`、`app/services/llm/agent.py`。

## 5. 数据库表结构

时间戳统一存 UTC（展示时转本地）。当前 `SCHEMA_VERSION = 7`。

### 5.1 基础设施表

| 表 | 主键 | 关键列 | 说明 |
| --- | --- | --- | --- |
| `schema_version` | `version` | `applied_at` | 轻量迁移记录 |
| `app_settings` | `id`（恒 1） | 业务列 + 采样/审计/策略/复习阈值/日志保留/口令哈希/工具开关 | 单行配置；列缺失/非法即回退默认（FR-902） |
| `api_key_secret` | `id`（恒 1） | `cipher`、`masked_hint`、`source` | 只存密文（FR-708） |
| `conversation` | `id`（uuid） | `kind`、`subject_id`、`round_count`、`compressed_at` | 记忆容器，测评/教学/复习各一条（FR-602） |
| `chat_round` | `id` | `conversation_id`、`round_index` | 唯一索引 `(conversation_id, round_index)` |
| `message` | `id` | `role`、`content`、`reasoning_content`、`tool_calls_json`、`is_summary`、`kind` | 摘要消息标记 `is_summary`；`kind=off_topic` 表示穿插提问（FR-411） |
| `usage_record` | `id` | `purpose`、`model`、prompt/cached/miss/completion/reasoning/total tokens、`duration_ms` | 命中与未命中都记录（FR-705）；`duration_ms` 用于累计耗时（FR-417） |

### 5.2 领域表

字段与取值约束的完整定义见需求规格说明书第 6 章与 `app/infra/storage/models.py`；要点：

| 表 | 关键约束 |
| --- | --- |
| `subject` | `status` 与 `session_state.state` 同源；`archived` 决定列表可见性（FR-103、FR-106） |
| `session_state` | 每个主题恒一行；`state` 迁移受状态机白名单约束（FR-410）；含 `awaiting_decision`（等三选一）、`last_action`（重跑上一条）、复习会话字段（`review_mode` / `review_node_id` / `review_checkpoint_id`）与 `adjacent_review_for`（避免重复回顾同一节点） |
| `assessment` | 进行中的测评每个主题至多一条（`get_running`） |
| `assessment_level` | 子领域水平（`none/basic/proficient`）+ `user_overridden`（FR-207） |
| `learning_path` | 同一主题只有一条 `is_active = 1`（FR-308）；历史版本保留（FR-307） |
| `knowledge_point` | `state` 覆盖 `not_started/learning/mastered/partial/skipped/review_needed`（FR-309）；`review_box` 与 `review_due_at` 承载间隔复习排期（FR-506） |
| `checkpoint` | 每个检查点必须有 `question`、非空 `expected_points` 与 `reference_answer`（可判定，FR-302） |
| `answer_record` | 每次判定落一条；`verdict` + `hit_points`/`missing_points` 使"放水"可追溯（FR-404）；`source ∈ {teach, review}`（FR-507） |
| `weak_point` | `reason ∈ {partial, skipped, show_answer, advanced}`（FR-409 的语义区分） |
| `study_note` | 节点笔记；`source ∈ {auto, user}`，手写覆盖自动小结（FR-801） |

### 5.3 升级策略

`create_all` **不会**修改已存在的表，因此 `app/infra/storage/db.py` 在 `init()` 中按
`SCHEMA_VERSION = 7` 执行幂等的列升级（先 `PRAGMA table_info` 检查，再 `ALTER TABLE ADD COLUMN`）。

**新增列时必须同时登记到 `_COLUMN_UPGRADES`**，否则老库升级后会在运行期报 "no such column"；
`tests/test_schema_upgrade.py` 用"手工删列/建旧表"复现该场景。

> 说明：`conversation.subject_id`、`usage_record.subject_id`/`conversation_id` 使用字符串外键
> 而非数据库级约束。单用户单实例场景下，级联删除由领域层显式完成（FR-104），
> 避免"先建表后改约束"的迁移负担。

## 6. HTTP 接口

### 6.1 通用约定

- 前缀 `/api`；
- **鉴权**：默认无鉴权（单用户自托管，NFR-101/102）。可选用访问口令（FR-903）：
  设置口令后，除 `/api/health` 与 `/api/auth/verify` 外的所有接口都要求
  `X-Access-Token` 请求头（或同名 cookie），未通过返回 **401**；
- 请求体与响应体均为 JSON（`{subject_id}` 为 uuid 字符串）；
- 响应中**永不含 API Key 明文或密文**，只有掩码（FR-708）；
- 错误响应统一为 `{"detail": "面向用户的中文说明"}`：
  - `401`：需要访问口令或口令不正确；
  - `404`：主题/子领域不存在；
  - `409`：请求本身合法但**当前状态不允许**（未生成路径就确认、还没进入教学就暂停/继续、非法状态迁移、复习前置条件不满足）；
  - `422`：入参校验失败（pydantic）或主题输入不合法（FR-102）；
- **流式端点**（下表标 ★）返回 `text/event-stream`，载荷见 §1。流式端点**一律返回 200**，
  业务错误通过 `error` 事件表达；只有"主题不存在"这类请求级错误才在建立流之前抛 404。
- **非 `/api` 路径由前端托管**：交付形态下后端把 `web/dist` 挂在所有 API 路由之后，
  未知前端路径回 `index.html`（SPA 深链接刷新不 404），带内容哈希的 `assets/*` 长缓存、
  `index.html` 不缓存。`/api/*` 的未知路径**不会**回退成 HTML，而是 `404 {"detail":"接口不存在"}`
  ——否则"接口写错"会表现为"页面莫名加载成功"。

### 6.2 主题与测评

| 方法 | 路径 | 说明 | 关联需求 |
| --- | --- | --- | --- |

| GET | `/api/subjects/{id}/nodes/{node_id}/history` | 该节点历次提问/作答/判定/反馈：`items[]` + `teach_count` + `review_count` | FR-802, FR-507 |
| PUT | `/api/subjects/{id}/nodes/{node_id}/note` | 编辑笔记，body `{"content"}`；返回 `{"note":{...}}`，手写内容 `source="user"` | FR-801 |

**复习产出**（`/review/start`、`/review/answer` 的响应，`GET /review` 的 `current` 同形）：

```text
{ text, phase, mode, node, verdict, confidence, feedback,
  hit_points[], missing_points[], promoted, resolved,
  fail_count, suggestion, node_index, node_total }
```

- `phase`：`question`（待作答）/ `passed`（通过）/ `failed`（未通过）
- `mode`：`weak`（薄弱点复习）/ `adjacent`（进入新节点前的回顾）
- `promoted` + `resolved` 同时为真表示"节点已升级 + 薄弱点已解除"
- 错误：请求合法但当前状态不允许 → **409**（与路径编辑、教学门禁一致）

**复习排期口径**（FR-505、FR-506）：

- 阶梯 `(1, 3, 7, 21, 60)` 天；节点变为 `mastered` 时盒号 = 1、到期 = 掌握时刻 + 1 天；
- 复习通过：盒号 + 1（封顶），到期 = 现在 + 阶梯[盒号]；复习不通过：回到第 1 档；
- 历史数据里没有排期的已掌握节点在读取复习概览时**幂等补齐**（教学/复习/路径重生成都可能产生
  mastered，逐个挂钩容易漏，而补齐是幂等的）；
- 主题列表的 `needs_review` = 有到期节点 **或** 已掌握节点超过 `review_interval_days` 天未触达。

**`source` 字段**：作答的 `source ∈ {teach, review}`（FR-507），笔记的 `source ∈ {auto, user}`
（FR-801）。档案页与节点历史据此区分来源；前端不显示这个字段时，用户会以为同一道题被问了两遍。

`purpose_overrides` 的形状（键即 `LlmPurpose`：`assess` / `plan` / `teach` / `judge` / `compress`；
缺省或非法一律回退为"继承全局"）：

```json
{ "judge": { "model": "pro", "thinking": "inherit", "reasoning_effort": "high" } }
```

- `model`：`inherit` / `default`（默认模型） / `pro`（深度模型）
- `thinking`：`inherit` / `on` / `off`
- `reasoning_effort`：`inherit` / `low` / `high` / `max`

`model_plan` 的形状：

```json
{ "judge": { "model": "deepseek-v4-pro", "thinking": true, "reasoning_effort": "high" } }
```

**`GET /api/usage` 字段**：

| 字段 | 说明 |
| --- | --- |
| `calls` / `prompt_tokens` / `cached_prompt_tokens` / `cache_miss_tokens` / `completion_tokens` / `reasoning_tokens` / `total_tokens` / `cache_hit_rate` | 全局聚合 |
| `duration_ms` | 累计模型调用耗时（毫秒）；老记录留空按 0 计 |
| `by_purpose` | `{用途: {calls, prompt_tokens, cached_prompt_tokens, cache_miss_tokens, completion_tokens, reasoning_tokens, total_tokens, cache_hit_rate, duration_ms}}` |
| `by_subject` | 按总 token 降序前 10：`[{subject_id, title, calls, total_tokens, cache_hit_rate, duration_ms}]` |
| `cache_hint` | 命中率异常（有调用但命中率为 0）时的中文排查提示，正常为 `null`（FR-705、FR-720） |
| `cost` | `{amount, currency, peak_tokens, off_peak_tokens, total_tokens}`（FR-706） |

**成本估算口径**（FR-706）：单价单位「元 / 百万 token」，表里存**高峰价**；
工作日 9:00–12:00、14:00–18:00（北京时间）为高峰，其余含周末为空闲且按半价。
**逐条记录按各自发生时刻计价**，不能拿当前时刻对总量一刀切。

**`GET /api/balance`**：成功时 `{ok: true, currency, total_balance, granted_balance,
topped_up_balance, is_available, message: "", category: null}`，金额为官方**字符串原样**；
失败时 `ok: false` + 中文 `message` + `category`。**永远返回 200**：余额是可选能力，
查不到不能挡住任何主流程（FR-710）。

  "storage": { "ok": true, "detail": "ok", "data_dir": "...", "schema_version": 7, "writable": true },

  目录权限、磁盘只读、句柄耗尽只有真写才看得出来；
- `usage` 是只读聚合，不产生模型调用；它失败只影响该字段，不拖垮健康检查。
